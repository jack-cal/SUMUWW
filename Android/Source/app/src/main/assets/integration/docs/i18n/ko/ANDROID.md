# SUMUWW Android 0.6.103 · 문서

SUMUWW Android 0.6.103 · 노드는 체인 데이터를 검증·저장·전파·조회합니다.

## 네트워크와 주소

공개 네트워크 이름은 `sumuww`이며 `dora`는 내부 별칭입니다. 아래 제네시스 해시도 확인하세요. 기본 주소는 압축된 secp256k1 공개키의 HASH160을 사용하는 witness v0 P2WPKH입니다. 필수 메모나 태그는 없습니다. 다른 네트워크의 주소나 체크섬이 잘못된 주소는 거부합니다. HD 주소별로 수신·거스름돈 분기와 인덱스를 기록하고, 비트코인과 파생 경로가 같다고 가정하지 마세요.

## 금액과 사용 가능한 출력

`_units`는 최소 단위의 정수, `_smw`는 소수점 8자리 문자열, `_dora`는 호환용 별칭입니다. `_sumuww` 금액 필드는 없습니다. 1 SMW는 100000000단위입니다. `gettxout`에는 `spendable` 필드가 없고 미성숙 채굴 보상도 반환할 수 있습니다. 다음 블록에서 보상을 쓰려면 확인이 100회 이상이어야 합니다. `listunspent`는 `spendable`로 걸러야 하며 `getaddressbalance`의 available 금액은 미성숙·대기 거래에서 사용 중인 자금을 제외합니다. 메모리풀의 새 출력은 확정 잔고가 아닙니다. 여러 페이지를 읽을 때 최신 블록이 바뀌지 않았는지 확인하고 선택한 입력을 다시 검증하세요.

1 SMW = 100,000,000 yugeon입니다. 자동 수수료는 로컬 관측값을 바탕으로 느림·보통·빠름을 제안하며, 확정 시간을 보장하지 않습니다. yugeon/vB 단위로 수수료율을 직접 입력할 수도 있습니다. 전송 전에 최종 수수료와 총액을 SMW로 확인하세요. 거부된 거래는 잔액에서 차감되지 않습니다.

1 SMW짜리 입력 하나를 쓸 때도 거스름돈이 있느냐에 따라 수수료가 달라집니다. 입력과 출력이 모두 P2WPKH이고 수수료율이 1유건/vB일 때, 0.99999890 SMW를 보내면 거스름돈 없이 수수료로 110유건을 냅니다. 같은 입력에서 0.8 SMW를 보내면 거스름돈 출력이 생겨 수수료가 141유건입니다. 지갑은 거스름돈을 나중에 쓸 비용까지 고려해 거스름돈 출력을 만들지 결정합니다. 남은 금액이 그 기준에 못 미치면 송금 확인 화면의 수수료에 포함됩니다. P2WPKH 입력의 크기를 추정할 때는 해시 유형을 포함해 서명 한 개를 최대 71바이트로 계산합니다.

`1 yugeon = 0.00000001 SMW` · `1 SMW = 100000000 yugeon`

| API / wallet | yugeon / SMW |
|---|---|
| minimum relay | 1 yugeon/vB |
| automatic cap | 0.01 SMW |
| manual cap | 1 SMW |
| manual rate | 1–100000 yugeon/vB |

자동 수수료는 현재 대기 거래량, 블록 처리 용량과 거래 우선순위를 반영합니다. 과거 블록의 수수료는 사용하지 않습니다. 대기량이 적으면 최소 수수료율을 유지합니다. 추천값은 갱신되며 최종 확인 시 수수료가 고정됩니다. 연결된 내 노드의 관측값이며 모든 노드의 상태를 뜻하지 않습니다.

지갑을 다시 열어도 이 노드에서 기록한 거래 교체 내역이 유지됩니다. 제거된 거래는 잔액에 반영되지 않습니다.

채굴 내역에서 블록별 신규 발행 보상, 거래 수수료 보상, 총보상을 구분합니다. 내 지갑이 받은 금액은 별도로 표시합니다. 보상을 일부만 청구한 경우에는 두 항목의 지급액을 임의로 나누지 않습니다. 노드는 수수료 추정을 포함한 RPC 28개를 제공하고, 서명된 거래를 검증·전파합니다.

## 거래·블록 조회

`getrawtransaction`은 활성 체인과 메모리풀을 조회하며 탈락한 분기에만 있는 거래는 찾지 않습니다. 입력은 이전 출력 위치를 가리키며 단일 송신 주소를 뜻하지 않습니다. `getblock`의 `verbose`는 불리언입니다. 보관된 비활성 블록은 `active=false`, `confirmations=-1`이고 해당 블록 해시로 원시 거래를 읽을 수 있습니다. `findspendingtransaction`은 활성 체인의 확정된 사용 거래만 찾으므로 null만으로 사용 가능하다고 판단하면 안 됩니다. `include_mempool=true`인 `gettxout`도 확인하세요. 확인 횟수와 활성 여부는 체인 재편 후 달라질 수 있습니다.

## 송금 수수료와 확인한 거래의 유지, 설치 호환성

수수료는 입력 금액 합계에서 출력 금액 합계를 뺀 값입니다. 지갑이 실제로 유효한 거스름돈을 만들 때만 견적에 거스름돈 출력의 크기를 포함합니다. 지갑의 거스름돈 기준에 못 미치는 잔액은 수수료에 합산되며, 최종 수수료와 총 출금액을 확인할 수 있습니다. 수수료율 단위는 yugeon/vB이며, 가상 크기는 거래 가중치를 4로 나눈 뒤 올림한 값입니다.

지갑은 입력과 출력을 한 번 선택한 뒤 그 거래 계획 그대로 서명합니다. 사용자가 확인하면 저장된 동일 서명 거래를 제출하며, 거래를 다시 구성하거나 수수료를 재계산하지 않습니다. 견적이 만료되거나 입력이 먼저 사용됐다면 새로 확인해야 합니다. 로컬 대기열에 접수됐다고 블록에서 확인된 것은 아닙니다.

일반 P2WPKH 송금은 low-R·low-S 서명을 사용하며 SIGHASH_ALL 바이트를 포함해 최대 71바이트입니다. 이는 지갑의 서명 생성·크기 추정 정책으로, 다른 유효 서명에 새 합의 제한을 적용하는 규칙이 아닙니다. 서명이 더 짧으면 실제 가상 크기는 추정치보다 작을 수 있습니다. 

## Android 앱 서명 호환성

지갑 파일 형식·주소·기존 코인은 바뀌지 않았습니다. 기존 암호화 지갑 백업을 새 앱에서 복원해 같은 지갑을 계속 사용할 수 있습니다. Android 노드 0.6.103와 지갑 1.1.14은 새로 생성한 배포 서명키를 사용합니다. 다른 키로 서명된 기존 앱 위에는 덮어쓰기 설치할 수 없습니다. 지갑의 암호화 백업과 정상적으로 작동하는 복구 수단을 확보할 때까지 기존 앱과 데이터를 보관하세요. 업데이트를 강제로 설치하려는 목적으로 기존 앱부터 삭제하지 마세요.
