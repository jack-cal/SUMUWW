# SUMUWW Android 0.6.103 · เอกสาร

SUMUWW Android 0.6.103 · โหนดตรวจสอบ เก็บ ส่งต่อ และให้ค้นข้อมูลเชน

## เครือข่ายและที่อยู่

เครือข่ายสาธารณะคือ `sumuww` มีชื่อภายในว่า `dora` ตรวจสอบแฮชบล็อกกำเนิดด้านล่าง ที่อยู่มาตรฐานใช้ witness v0 P2WPKH และ HASH160 ของกุญแจสาธารณะ secp256k1 แบบบีบอัด ไม่บังคับ memo หรือ tag ปฏิเสธที่อยู่ผิดเครือข่ายและ checksum ผิด บันทึกแขนง HD รับเงิน/เงินทอนและดัชนี อย่าสมมติว่าใช้เส้นทางสร้างกุญแจแบบ Bitcoin

## จำนวนเงินและเอาต์พุตที่ใช้ได้

`_units` คือจำนวนเต็มหน่วยย่อยสุด `_smw` คือข้อความทศนิยม 8 หลัก `_dora` คือชื่อเพื่อความเข้ากันได้ ไม่มีฟิลด์จำนวนเงิน `_sumuww` และ 1 SMW = 100000000 หน่วย `gettxout` ไม่มี `spendable` และอาจคืน coinbase ที่ยังไม่ครบกำหนด ต้องมีอย่างน้อย 100 การยืนยันจึงใช้ในบล็อกถัดไปได้ กรอง `listunspent` ด้วย `spendable`; available ใน `getaddressbalance` ตัดเงินที่ยังไม่ครบกำหนดและถูกใช้ในธุรกรรมรอออก เอาต์พุตใหม่ใน mempool ยังไม่ยืนยัน ตรวจยอดสายโซ่ระหว่างหน้าและตรวจอินพุตที่เลือกซ้ำ

1 SMW = 100,000,000 yugeon ค่าธรรมเนียมอัตโนมัติมีสามระดับจากข้อมูลที่โหนดสังเกตได้ และไม่รับประกันเวลายืนยัน คุณสามารถระบุอัตรา yugeon/vB เองได้ โปรดตรวจสอบค่าธรรมเนียมสุดท้ายและยอดรวมเป็น SMW ก่อนส่ง ธุรกรรมที่ถูกปฏิเสธจะไม่หักยอดคงเหลือ

เมื่อใช้อินพุต 1 รายการมูลค่า 1 SMW ค่าธรรมเนียมจะขึ้นอยู่กับว่าต้องทอนเงินหรือไม่ หากอินพุตและเอาต์พุตทั้งหมดเป็น P2WPKH และอัตราค่าธรรมเนียมคือ 1 yugeon/vB การส่ง 0.99999890 SMW จะเสียค่าธรรมเนียม 110 yugeon โดยไม่มีเงินทอน แต่ถ้าส่ง 0.8 SMW จากอินพุตเดียวกัน จะมีเอาต์พุตสำหรับเงินทอนเพิ่มขึ้น และค่าธรรมเนียมจะเป็น 141 yugeon กระเป๋าจะคืนเงินทอนเมื่อยอดที่เหลือหลังหักค่าธรรมเนียมถึงเกณฑ์ขั้นต่ำที่คำนึงถึงค่าใช้จ่ายในการใช้เงินทอนนั้นในภายหลัง หากเหลือน้อยกว่าเกณฑ์ ยอดที่เหลือจะรวมอยู่ในค่าธรรมเนียมที่แสดงก่อนยืนยัน เมื่อประเมินขนาดอินพุตของกระเป๋าแบบ Native SegWit (P2WPKH) ระบบจะคิดขนาดลายเซ็นรวมชนิดแฮชไม่เกิน 71 ไบต์

`1 yugeon = 0.00000001 SMW` · `1 SMW = 100000000 yugeon`

| API / wallet | yugeon / SMW |
|---|---|
| minimum relay | 1 yugeon/vB |
| automatic cap | 0.01 SMW |
| manual cap | 1 SMW |
| manual rate | 1–100000 yugeon/vB |

ค่าธรรมเนียมอัตโนมัติคำนวณจากปริมาณข้อมูลที่รอ ความจุของบล็อก และลำดับความสำคัญของธุรกรรม โดยไม่ใช้ค่าธรรมเนียมจากบล็อกเก่า หากคิวสั้นจะใช้อัตราขั้นต่ำ ตัวอย่างจะอัปเดตและค่าธรรมเนียมจะคงที่เมื่อยืนยันขั้นสุดท้าย ข้อมูลเป็นของโหนดในเครื่องที่เชื่อมต่ออยู่ ไม่ใช่ทุกโหนด

ประวัติการแทนที่ธุรกรรมที่โหนดนี้บันทึกไว้จะยังอยู่หลังเปิดกระเป๋าใหม่ ธุรกรรมที่ถูกนำออกไม่กระทบยอดคงเหลือ

ประวัติการขุดแยกเหรียญออกใหม่ ค่าธรรมเนียมธุรกรรม และรางวัลรวมของแต่ละบล็อก โดยแสดงยอดที่กระเป๋าของคุณได้รับแยกต่างหาก หากรับรางวัลเพียงบางส่วน ระบบจะไม่คาดเดาการแบ่งยอดทั้งสองส่วน โหนดมี RPC 28 วิธี รวมการประมาณค่าธรรมเนียม และตรวจสอบพร้อมส่งต่อธุรกรรมที่ลงนามแล้ว

## ค้นหาธุรกรรมและบล็อก

`getrawtransaction` ค้นในสายโซ่ที่ใช้งานและ mempool ไม่ค้นธุรกรรมที่อยู่เฉพาะแขนงกำพร้า อินพุตระบุเอาต์พุตก่อนหน้า ไม่ใช่ที่อยู่ผู้ส่งเดียว `getblock` รับ `verbose` แบบ Boolean บล็อกที่เก็บแต่ไม่ใช้งานมี `active=false`, `confirmations=-1` ยังอ่านธุรกรรมดิบผ่านแฮชบล็อกได้ `findspendingtransaction` ค้นเฉพาะการใช้ที่ยืนยันในสายโซ่ปัจจุบัน null ไม่พิสูจน์ว่าใช้ได้ ตรวจ `gettxout` ด้วย `include_mempool=true` จำนวนยืนยันและสถานะใช้งานอาจเปลี่ยนเมื่อจัดสายโซ่ใหม่

## ค่าธรรมเนียม ธุรกรรมที่ตรวจสอบแล้ว และความเข้ากันได้

ค่าธรรมเนียมคือยอดรวมอินพุตลบด้วยยอดรวมเอาต์พุต การประมาณขนาดจะนับเอาต์พุตเงินทอนเฉพาะเมื่อกระเป๋าสร้างเงินทอนที่ผ่านเกณฑ์จริงเท่านั้น หากยอดที่เหลือต่ำกว่าเกณฑ์ของกระเป๋า ยอดนั้นจะรวมเป็นค่าธรรมเนียม โดยแสดงค่าธรรมเนียมสุดท้ายและยอดหักรวมให้ตรวจสอบ อัตราค่าธรรมเนียมใช้หน่วย yugeon/vB ส่วนขนาดเสมือนคือน้ำหนักธุรกรรมหารด้วยสี่แล้วปัดขึ้น

กระเป๋าเลือกอินพุตและเอาต์พุตเพียงครั้งเดียว แล้วลงนามตามแผนธุรกรรมเดียวกัน เมื่อยืนยันจะส่งธุรกรรมที่ลงนามและเก็บไว้ โดยไม่สร้างธุรกรรมใหม่หรือคำนวณค่าธรรมเนียมซ้ำ หากรายการประมาณการหมดอายุหรืออินพุตถูกใช้ไปแล้ว ต้องตรวจสอบใหม่ การรับเข้าคิวภายในเครื่องยังไม่ใช่การยืนยันในบล็อก

การชำระเงิน P2WPKH ทั่วไปใช้ลายเซ็น low-R และ low-S ที่ยาวไม่เกิน 71 ไบต์รวมไบต์ SIGHASH_ALL นี่คือนโยบายการลงนามและการประมาณขนาดของกระเป๋า ไม่ใช่ข้อจำกัดฉันทามติใหม่สำหรับลายเซ็นที่ถูกต้องอื่น ๆ ลายเซ็นที่สั้นกว่าอาจทำให้ขนาดเสมือนจริงเล็กกว่าค่าประมาณ อัตราที่แนะนำยังคงอ้างอิงคิวภายในโหนด 

## ความเข้ากันได้ของลายเซ็น Android

รูปแบบไฟล์กระเป๋า ที่อยู่ และเหรียญเดิมไม่เปลี่ยนแปลง สามารถกู้คืนข้อมูลสำรองกระเป๋าแบบเข้ารหัสเดิมในแอปใหม่เพื่อใช้กระเป๋าใบเดิมต่อได้ โหนด Android 0.6.103 และกระเป๋า 1.1.14 ใช้กุญแจลงนามรุ่นเผยแพร่ที่สร้างใหม่ จึงติดตั้งทับแอปเดิมที่ลงนามด้วยกุญแจต่างกันไม่ได้ โปรดเก็บแอปเดิมและข้อมูลไว้จนกว่าจะมีข้อมูลสำรองกระเป๋าแบบเข้ารหัสและวิธีกู้คืนที่ใช้งานได้ อย่าถอนการติดตั้งแอปเดิมเพียงเพื่อบังคับติดตั้งรุ่นอัปเดต
