# SUMUWW · ドキュメント

SUMUWW PC 0.57.51 · ノードはチェーンデータの検証・保存・伝播・照会を担います。

## 署名形式

任意のソース SDK は鍵やネットワークを使わずに取引を組み立て、受け取った署名を検証します。署名プログラムでもノードのコマンドでもありません。P2WPKH 送金の制限は例の形式に対するもので、ノード全体の制限ではありません。従来の個人用ウォレットは使えます。

## RPC・HTTP API

validateaddress はチェックサムと選択したネットワークを確認します。decoderawtransaction の decoded_only は解析のみを示し、署名の有効性や承認を示しません。OP_RETURN 出力は外部プログラム用データを保存します。 ノードに手数料照会、送信前検証、RBF の置換状態、ブロック順のデータ取得を追加しました。置換取引の検証後にのみ、元の未承認取引を削除します。複数署名とロック出力は分離環境での有効化試験用に実装済みですが、公開ネットワークではまだ有効ではありません。

## 検証

依存関係を導入し、ソースから python examples/node_contract.py を実行します。公開テスト鍵と一時的な regtest で送信・拒否・承認・再編成・データ保存を確認します。実資金、ユーザープロファイル、ハードウェア署名器は使用しません。

```text
network: sumuww (dora)
genesis: 00000032e243a8c71b449b13c2da733dd329f308a75aa4358f3f22707a28af97
HRP: sumuww
P2P magic: d052470c
1 SMW = 100000000 yugeon
```

## 送金手数料、確認済み取引と互換性

手数料は入力金額の合計から出力金額の合計を引いた値です。ウォレットが実際に有効なお釣りを作る場合だけ、見積もりにお釣り出力のサイズを含めます。ウォレットの基準に満たない残額は手数料に加えられ、最終手数料と総引落額が確認画面に表示されます。料率の単位は yugeon/vB です。仮想サイズは取引のウェイトを4で割り、切り上げた値です。

ウォレットは入力と出力を一度だけ選び、その同じ取引プランに署名します。確認後は保存済みの署名付き取引を送信し、取引の再構成や手数料の再計算は行いません。見積もりが期限切れになった場合や入力が先に使用された場合は、再確認が必要です。ローカルの待機キューへの受理は、ブロックでの承認とは異なります。

通常の P2WPKH 送金では low-R・low-S 署名を生成し、SIGHASH_ALL バイトを含めて最大71バイトとします。これはウォレットの署名・サイズ見積もりの方針であり、ほかの有効な署名に新たなコンセンサス制限を設けるものではありません。署名が短ければ実際の仮想サイズは見積もりより小さくなることがあります。推奨料率は引き続き自ノードの待機キューに基づきます。
