# SUMUWW · ノードの運用

通常は外向きの接続を10件開き、主にブロックと取引の中継に使います。検証済みの予備接続をブロックの中継に使うことも、別のノードを探すために一時的に11件目を開くこともあります。合計の上限は125件です。外部からの接続は最大117件、外向きが10件なら最大115件です。 PC版では、接続中のノードの合計数だけを表示するようになりました。 各採掘端末が自分でブロックを作成します。PCノードは完成したブロックを中継し、スマートフォンからの採掘ジョブの要求と計算結果の提出を拒否します。

再起動時は、このノードが最後に検証したブロックから再開し、新しいブロックを確認します。保存した検証記録が見つからない場合や内容が一致しない場合は、保存済みの履歴を再検証します。


SUMUWW PC 0.57.61 · ノードはチェーンデータの検証・保存・伝播・照会を担います。

## ネットワークとアドレス

公開ネットワークは `sumuww`、内部の別名は `dora` です。下記のジェネシスハッシュも確認してください。標準アドレスは圧縮secp256k1公開鍵のHASH160を使うwitness v0 P2WPKHです。必須のメモやタグはありません。ネットワーク違いや不正なチェックサムは拒否します。HDアドレスの受取・お釣りの分岐とインデックスを記録し、Bitcoinと同じ導出パスとは考えないでください。

## 認証と制限

RPCは明示的に有効化し、数値ループバック `127.0.0.1:18443` と非公開のBearerトークンを使います。ウォレット解除や遠隔署名は公開しません。ローカルサービスか認証済みトンネルを使用してください。ブラウザーのOrigin/Referer要求は拒否します。JSON-RPCはPOST `/rpc`、オブジェクトまたは配列の `params`、`id` を使い、通知にはHTTP 204を返します。上限は本文8004096バイト、ヘッダー8192バイト、バッチ16、同時要求16、期限10秒。ページのlimitは1–1000、offsetは0–1000000です。メソッド28個とREST経路11個を提供します。

## 取引・ブロックの照会

`getrawtransaction` はアクティブチェーンとメモリプールを検索し、孤立分岐だけの取引は検索しません。入力は過去の出力を指し、一意の送信元アドレスを表しません。`getblock` の `verbose` は真偽値です。保存済み非アクティブブロックは `active=false`、`confirmations=-1` となり、生の取引はブロックハッシュで取得できます。`findspendingtransaction` はアクティブチェーンの確定済み使用取引だけを探すため、nullだけで使用可能とは判断できません。`include_mempool=true` の `gettxout` も確認してください。確認数とactive状態は再編で変わり得ます。

## 検証

依存関係を導入し、ソースから python examples/node_contract.py を実行します。公開テスト鍵と一時的な regtest で送信・拒否・承認・再編成・データ保存を確認します。実資金、ユーザープロファイル、ハードウェア署名器は使用しません。

```text
network: sumuww (dora)
genesis: 00000032e243a8c71b449b13c2da733dd329f308a75aa4358f3f22707a28af97
HRP: sumuww
P2P magic: d052470c
1 SMW = 100000000 yugeon
```

## 送金手数料、確認済み取引と互換性

手数料は入力金額の合計から出力金額の合計を引いた値です。ウォレットが実際に有効なお釣りを作る場合だけ、見積もりにお釣り出力のサイズを含めます。ウォレットの基準に満たない残額は手数料に加えられ、最終手数料と総引落額が確認画面に表示されます。料率の単位は yugeon/vB です。仮想サイズは取引のウェイトを4で割り、切り上げた値です。

ウォレットは入力と出力を一度だけ選び、その同じ取引プランに署名します。確認後は保存済みの署名付き取引を送信し、取引の再構成や手数料の再計算は行いません。見積もりが期限切れになった場合や入力が先に使用された場合は、再確認が必要です。ローカルの待機キューへの受理は、ブロックでの承認とは異なります。

通常の P2WPKH 送金では low-R・low-S 署名を生成し、SIGHASH_ALL バイトを含めて最大71バイトとします。これはウォレットの署名・サイズ見積もりの方針であり、ほかの有効な署名に新たなコンセンサス制限を設けるものではありません。署名が短ければ実際の仮想サイズは見積もりより小さくなることがあります。推奨料率は引き続き自ノードの待機キューに基づきます。Bitcoin と同様のサイズ計算を採用しても、Bitcoin ネットワークの料率を使うわけではありません。

## Windows の I2P コンポーネントとセキュリティ検査

Windows 配布物には公式 i2pd 3.0.0 と更新済みのハッシュ値・初期接続用証明書を含めています。記録した検査では、Defender は公式の I2P 実行ファイルと元の ZIP を引き続き検出しました。公式ハッシュとの一致だけでは、安全性や誤検出を確定できません。ファイル単位の除外設定は登録した PC にだけ有効で、公開パッケージから自動設定されることはありません。ほかの PC では同じファイルがブロックされる場合があります。

有効なバージョン応答を受け取ると、ノードは相手が確認応答を返すための時間を確保します。同じノードに向かう接続が二つある場合は、どちらかで同期が完了するまで利用できる経路を維持します。 内蔵の自己診断では、接続証明が届く前に、有効なプルーフ・オブ・ワークを持つブロックを受け入れます。その後、接続証明に含まれる3人の証人の署名、他のノードへの転送、再起動後の保存状態を確認します。
