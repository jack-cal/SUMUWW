# SUMUWW · การใช้งานโหนด

โดยปกติโหนดจะเปิดการเชื่อมต่อขาออก 10 รายการ ส่วนใหญ่ใช้ส่งต่อทั้งบล็อกและธุรกรรม โหนดอาจใช้การเชื่อมต่อสำรองที่เคยตรวจสอบแล้วเพื่อส่งต่อบล็อก และเปิดการเชื่อมต่อที่ 11 ชั่วคราวเพื่อค้นหาโหนดอื่น การเชื่อมต่อทั้งหมดจำกัดไว้ที่ 125 รายการ ขาเข้าได้สูงสุด 117 รายการ หรือ 115 รายการเมื่อมีขาออก 10 รายการ ตอนนี้แอปบนคอมพิวเตอร์แสดงเฉพาะจำนวนโหนดที่เชื่อมต่อทั้งหมด อุปกรณ์ขุดแต่ละเครื่องสร้างบล็อกของตัวเอง โหนดพีซีจะส่งต่อบล็อกที่เสร็จแล้ว และปฏิเสธคำของานขุดและผลการคำนวณจากโทรศัพท์

เมื่อเริ่มทำงานอีกครั้ง โหนดจะทำงานต่อจากบล็อกล่าสุดที่ตรวจสอบไว้ในเครื่องและตรวจสอบบล็อกใหม่ หากไม่พบบันทึกการตรวจสอบที่เก็บไว้หรือข้อมูลไม่ตรงกัน โหนดจะตรวจสอบประวัติที่เก็บไว้อีกครั้ง


SUMUWW PC 0.57.61 · โหนดตรวจสอบ เก็บ ส่งต่อ และให้ค้นข้อมูลเชน

## เครือข่ายและที่อยู่

เครือข่ายสาธารณะคือ `sumuww` มีชื่อภายในว่า `dora` ตรวจสอบแฮชบล็อกกำเนิดด้านล่าง ที่อยู่มาตรฐานใช้ witness v0 P2WPKH และ HASH160 ของกุญแจสาธารณะ secp256k1 แบบบีบอัด ไม่บังคับ memo หรือ tag ปฏิเสธที่อยู่ผิดเครือข่ายและ checksum ผิด บันทึกแขนง HD รับเงิน/เงินทอนและดัชนี อย่าสมมติว่าใช้เส้นทางสร้างกุญแจแบบ Bitcoin

## การยืนยันตัวตนและขีดจำกัด

เปิด RPC อย่างชัดเจนที่ loopback ตัวเลข `127.0.0.1:18443` ด้วย Bearer token ส่วนตัว ไม่มีการปลดล็อกกระเป๋าหรือลงนามระยะไกล ใช้บริการในเครื่องหรืออุโมงค์ที่ยืนยันตัวตน คำขอจากเบราว์เซอร์ที่มี Origin/Referer ถูกปฏิเสธ JSON-RPC ใช้ POST `/rpc`, `params` แบบออบเจ็กต์/อาร์เรย์ และ `id`; notification ตอบ HTTP 204 ขีดจำกัด: body 8004096 ไบต์, header 8192, batch 16, คำขอพร้อมกัน 16, เวลา 10 วินาที; limit 1–1000, offset 0–1000000 มี 28 เมธอดและ 11 เส้นทาง REST

## ค้นหาธุรกรรมและบล็อก

`getrawtransaction` ค้นในสายโซ่ที่ใช้งานและ mempool ไม่ค้นธุรกรรมที่อยู่เฉพาะแขนงกำพร้า อินพุตระบุเอาต์พุตก่อนหน้า ไม่ใช่ที่อยู่ผู้ส่งเดียว `getblock` รับ `verbose` แบบ Boolean บล็อกที่เก็บแต่ไม่ใช้งานมี `active=false`, `confirmations=-1` ยังอ่านธุรกรรมดิบผ่านแฮชบล็อกได้ `findspendingtransaction` ค้นเฉพาะการใช้ที่ยืนยันในสายโซ่ปัจจุบัน null ไม่พิสูจน์ว่าใช้ได้ ตรวจ `gettxout` ด้วย `include_mempool=true` จำนวนยืนยันและสถานะใช้งานอาจเปลี่ยนเมื่อจัดสายโซ่ใหม่

## ผลการตรวจสอบ

ติดตั้งส่วนประกอบที่จำเป็นแล้วรัน python examples/node_contract.py จากซอร์ส กุญแจทดสอบสาธารณะและ regtest ชั่วคราวตรวจการส่ง การปฏิเสธ การยืนยัน การจัดเชนใหม่ และการเก็บข้อมูล โดยไม่ใช้เงินจริง โปรไฟล์ผู้ใช้ หรืออุปกรณ์ลงนาม

## ค่าธรรมเนียม ธุรกรรมที่ตรวจสอบแล้ว และความเข้ากันได้

ค่าธรรมเนียมคือยอดรวมอินพุตลบด้วยยอดรวมเอาต์พุต การประมาณขนาดจะนับเอาต์พุตเงินทอนเฉพาะเมื่อกระเป๋าสร้างเงินทอนที่ผ่านเกณฑ์จริงเท่านั้น หากยอดที่เหลือต่ำกว่าเกณฑ์ของกระเป๋า ยอดนั้นจะรวมเป็นค่าธรรมเนียม โดยแสดงค่าธรรมเนียมสุดท้ายและยอดหักรวมให้ตรวจสอบ อัตราค่าธรรมเนียมใช้หน่วย yugeon/vB ส่วนขนาดเสมือนคือน้ำหนักธุรกรรมหารด้วยสี่แล้วปัดขึ้น

กระเป๋าเลือกอินพุตและเอาต์พุตเพียงครั้งเดียว แล้วลงนามตามแผนธุรกรรมเดียวกัน เมื่อยืนยันจะส่งธุรกรรมที่ลงนามและเก็บไว้ โดยไม่สร้างธุรกรรมใหม่หรือคำนวณค่าธรรมเนียมซ้ำ หากรายการประมาณการหมดอายุหรืออินพุตถูกใช้ไปแล้ว ต้องตรวจสอบใหม่ การรับเข้าคิวภายในเครื่องยังไม่ใช่การยืนยันในบล็อก

การชำระเงิน P2WPKH ทั่วไปใช้ลายเซ็น low-R และ low-S ที่ยาวไม่เกิน 71 ไบต์รวมไบต์ SIGHASH_ALL นี่คือนโยบายการลงนามและการประมาณขนาดของกระเป๋า ไม่ใช่ข้อจำกัดฉันทามติใหม่สำหรับลายเซ็นที่ถูกต้องอื่น ๆ ลายเซ็นที่สั้นกว่าอาจทำให้ขนาดเสมือนจริงเล็กกว่าค่าประมาณ อัตราที่แนะนำยังคงอ้างอิงคิวภายในโหนด การคำนวณขนาดในแนวทางเดียวกับ Bitcoin ไม่ได้หมายความว่าใช้อัตราค่าธรรมเนียมของเครือข่าย Bitcoin

## ส่วนประกอบ I2P ของ Windows และการตรวจสอบความปลอดภัย

แพ็กเกจ Windows มี i2pd 3.0.0 อย่างเป็นทางการ พร้อมแฮชและใบรับรองสำหรับการเชื่อมต่อเริ่มต้นที่อัปเดตแล้ว ในผลตรวจที่บันทึกไว้ Defender ยังตรวจพบไฟล์โปรแกรม I2P และ ZIP ต้นฉบับอย่างเป็นทางการ แฮชที่ตรงกับต้นทางไม่ใช่หลักฐานยืนยันความปลอดภัยหรือยืนยันว่าเป็นการตรวจผิด ข้อยกเว้นไฟล์ในเครื่องมีผลเฉพาะคอมพิวเตอร์ที่ตั้งค่าไว้ แพ็กเกจสาธารณะจะไม่เพิ่มข้อยกเว้นนี้ให้ เครื่องอื่นยังอาจบล็อกไฟล์เดียวกันได้
