# SUMUWW · 문서

1 SMW짜리 입력 하나를 쓸 때도 거스름돈이 있느냐에 따라 수수료가 달라집니다. 입력과 출력이 모두 P2WPKH이고 수수료율이 1유건/vB일 때, 0.99999890 SMW를 보내면 거스름돈 없이 수수료로 110유건을 냅니다. 같은 입력에서 0.8 SMW를 보내면 거스름돈 출력이 생겨 수수료가 141유건입니다. 지갑은 거스름돈을 나중에 쓸 비용까지 고려해 거스름돈 출력을 만들지 결정합니다. 남은 금액이 그 기준에 못 미치면 송금 확인 화면의 수수료에 포함됩니다. P2WPKH 입력의 크기를 추정할 때는 해시 유형을 포함해 서명 한 개를 최대 71바이트로 계산합니다.


SUMUWW PC 0.57.51 · 노드는 체인 데이터를 검증·저장·전파·조회합니다.

## 서명 형식

선택 사항인 소스 SDK는 키나 네트워크 없이 거래를 조립하고 전달받은 서명을 검증합니다. 서명 프로그램이나 노드 명령이 아닙니다. P2WPKH 일반송금 제한은 예제 형식에만 적용되며 노드 전체의 제한이 아닙니다. 기존 개인 지갑은 그대로 사용할 수 있습니다.

## RPC·HTTP API

validateaddress는 체크섬과 선택한 네트워크를 검사합니다. decoderawtransaction의 decoded_only는 내용 해석만 뜻하며 서명 검증이나 확정을 뜻하지 않습니다. 기존 OP_RETURN 출력은 외부 프로그램용 데이터를 보존합니다. 노드에 수수료 조회, 전파 전 검증, RBF 교체 상태와 블록 순서에 따른 데이터 기록 조회를 추가했습니다. 교체 거래를 검증한 뒤에만 기존 대기 거래를 제거합니다. 다중 서명과 잠금 출력은 별도 활성화 시험용으로 구현했으며, 운영망에서는 아직 활성화되지 않았습니다.

## 검증

의존성을 설치한 소스에서 python examples/node_contract.py를 실행합니다. 공개 시험 키와 임시 regtest로 거래 제출·거부·확정·체인 재편·데이터 보존을 시험합니다. 실제 자금, 사용자 프로필, 하드웨어 서명기는 사용하지 않습니다.

## 송금 수수료와 확인한 거래의 유지, 설치 호환성

수수료는 입력 금액 합계에서 출력 금액 합계를 뺀 값입니다. 지갑이 실제로 유효한 거스름돈을 만들 때만 견적에 거스름돈 출력의 크기를 포함합니다. 지갑의 거스름돈 기준에 못 미치는 잔액은 수수료에 합산되며, 최종 수수료와 총 출금액을 확인할 수 있습니다. 수수료율 단위는 yugeon/vB이며, 가상 크기는 거래 가중치를 4로 나눈 뒤 올림한 값입니다.

지갑은 입력과 출력을 한 번 선택한 뒤 그 거래 계획 그대로 서명합니다. 사용자가 확인하면 저장된 동일 서명 거래를 제출하며, 거래를 다시 구성하거나 수수료를 재계산하지 않습니다. 견적이 만료되거나 입력이 먼저 사용됐다면 새로 확인해야 합니다. 로컬 대기열에 접수됐다고 블록에서 확인된 것은 아닙니다.

일반 P2WPKH 송금은 low-R·low-S 서명을 사용하며 SIGHASH_ALL 바이트를 포함해 최대 71바이트입니다. 이는 지갑의 서명 생성·크기 추정 정책으로, 다른 유효 서명에 새 합의 제한을 적용하는 규칙이 아닙니다. 서명이 더 짧으면 실제 가상 크기는 추정치보다 작을 수 있습니다. 수수료율은 계속 내 노드의 대기열을 기준으로 제안하므로, 비트코인과 크기 계산 방식을 맞췄다고 비트코인 네트워크의 수수료율을 사용하는 것은 아닙니다.

## Windows I2P 구성요소와 보안 검사

Windows 배포본에는 공식 i2pd 3.0.0과 갱신한 체크섬·초기 연결용 인증서를 포함합니다. 기록된 검사에서 Defender는 공식 I2P 실행 파일과 원본 ZIP을 여전히 탐지했습니다. 공식 해시와 일치한다는 사실만으로 안전하거나 오탐이라고 확정할 수는 없습니다. 파일별 보안 예외는 등록한 PC에만 적용되며, 공개 배포본이 자동으로 등록하지 않습니다. 다른 PC에서는 같은 파일이 차단될 수 있습니다.
