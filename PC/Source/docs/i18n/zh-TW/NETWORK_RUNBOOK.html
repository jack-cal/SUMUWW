SUMUWW · 節點運作

節點通常建立 10 個對外連線，大部分用來轉送區塊和交易。節點可以透過已驗證的備用連線轉送區塊，也可以暫時開啟第 11 個連線來尋找其他節點。連線總數上限為 125。連入連線最多 117 個，有 10 個對外連線時則最多 115 個。 桌面版現在只顯示已連線節點的總數。 每台挖礦裝置自行建立區塊。電腦節點會轉送已完成的區塊，並拒絕手機提出的挖礦工作請求及送出的計算結果。

重新啟動後，節點會從上次在本機驗證的區塊繼續，檢查新區塊。如果儲存的驗證紀錄遺失或資料不符，節點會重新驗證已儲存的歷史紀錄。

SUMUWW PC 0.57.61 · 節點負責驗證、儲存、傳播與查詢鏈上資料。

網路與位址

公開網路為 sumuww，內部別名為 dora。請核對下方創世區塊雜湊。原生位址採用 witness v0 P2WPKH，以及壓縮 secp256k1 公開金鑰的 HASH160。無須強制 memo 或 tag。應拒絕網路錯誤或檢查碼無效的位址。記錄 HD 收款/找零分支及索引，不要假定與 Bitcoin 的衍生路徑相同。

驗證與限制

明確啟用 RPC，使用數字回送位址 127.0.0.1:18443 及私有 Bearer token。不提供錢包解鎖或遠端簽章。透過本機服務或已驗證通道連線；拒絕瀏覽器 Origin/Referer 請求。JSON-RPC 使用 POST /rpc、物件/陣列 params 及 id；通知回傳 HTTP 204。限制：本文 8004096 位元組、標頭 8192、批次 16、同時請求 16、期限 10 秒；limit 1–1000、offset 0–1000000。共有 28 個方法及 11 條 REST 路由。

交易與區塊查詢

getrawtransaction 查詢有效鏈及記憶池，不查詢僅存在於孤立分支的交易。輸入指向之前的輸出，並非唯一傳送地址。getblock 的 verbose 為布林值；已保存的非有效區塊為 active=false、confirmations=-1，仍可用區塊雜湊取得原始交易。findspendingtransaction 僅查有效鏈上已確認的花費，null 不證明可用。還須查詢 include_mempool=true 的 gettxout。確認數與有效狀態都可能隨重組改變。

查驗

安裝相依套件後，從原始碼執行 python examples/node_contract.py。公開測試金鑰與暫時 regtest 驗證提交、拒絕、確認、鏈重組及資料保存，不使用真實資金、使用者設定檔或硬體簽署器。

交易手續費、確認內容與相容性

手續費等於輸入金額總和減去輸出金額總和。只有錢包實際建立符合門檻的找零時，估算才會計入找零輸出的大小。低於錢包找零門檻的餘額會併入手續費，確認前會顯示最終手續費與總扣款。費率單位為 yugeon/vB；虛擬大小等於交易權重除以四後無條件進位。

錢包只選擇一次輸入與輸出，並依同一筆交易計畫產生簽章。確認後提交的是已儲存的簽署交易，不會重新組合交易或重算手續費。報價逾期或輸入已被花費時，必須重新核對。進入本機待處理佇列，並不代表已獲得區塊確認。

一般 P2WPKH 轉帳使用 low-R、low-S 簽章，連同 SIGHASH_ALL 位元組在內最多 71 位元組。這是錢包的簽章與大小估算政策，並非對其他有效簽章新增的共識限制。簽章較短時，實際虛擬大小可能小於估算值。建議費率仍依本機節點的待處理佇列計算；採用與 Bitcoin 相近的大小計算方式，不表示沿用 Bitcoin 網路的費率。

Windows I2P 元件與安全性檢查

Windows 套件包含官方 i2pd 3.0.0，並同步更新雜湊值與初始連線所需的憑證。在已記錄的檢查中，Defender 仍會偵測到官方 I2P 執行檔及原始 ZIP。雜湊值與官方相符，不能證明安全或確定為誤判。本機檔案排除設定只對登錄設定的電腦生效，公開套件不會自動加入排除設定；其他電腦仍可能封鎖相同檔案。
