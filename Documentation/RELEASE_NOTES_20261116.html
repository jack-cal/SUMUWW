Whitepaper 2.4

Ordinary payment quotes now include a change output only when viable change is actually created. The same selected inputs, exact outputs and fee are signed and retained for confirmation; submission does not reconstruct the transaction. Ordinary wallet P2WPKH signatures use low-R/low-S and a maximum 71-byte signature item including its hash-type byte. This is wallet policy, not a new consensus limit. See the detailed payment policy.

Android: changed signing identity

The Android node and wallet packages in this update are signed with a newly generated release key. They cannot update an older installation signed with a different certificate. The node package is org.sumuww.miner; the ordinary wallet is org.sumuww.wallet.current. The new certificate SHA-256 is:

e609c42039cd7b9aa47d921d016ed305b6091dd0b7bb5a820f7b373c3ad66f38

Keep the installed app and its data until an encrypted wallet backup and a working recovery method are secured. Do not uninstall an old application merely to force installation. The new signing identity is not advertised as an automatic in-place update to the previous Android signing lineage.

Documentation and verification

Whitepaper 2.4 and the affected protocol, wallet and operating explanations distinguish actual transaction fees, fee-rate suggestions, change policy, quote reuse and local signature limits.

Existing issuance, valid chain history, block acceptance, difficulty and connection-proof activation rules are preserved. P2P Full/Light trading and Explorer retain their separate documented scope.

After a valid version reply, the node gives its peer time to acknowledge it. If two outgoing connections reach the same node, it keeps an available route until one has synchronized.
